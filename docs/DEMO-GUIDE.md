# 小X校园助手 · 使用与算法演示指南

版本：v0.5.0 · 更新：2026-10-06

这是面向多所高校学生的纯前端交互原型。它用可点击的页面，演示校园问答、文件依据、申请条件核对、材料准备，以及从对话形成个性化推荐的产品关系。“小X”是暂定名称，学校、制度、人物和材料均为虚构示例。

## 1. 怎样打开，怎样分享

**直接体验：**下载预览压缩包，解压后双击“校园助手-双击打开.html”。无需安装开发环境，也不需要联网。Windows 用户也可以双击 start-preview.cmd。请先解压，不要在压缩包预览窗口内运行。

**阅读说明：**同一目录中的“使用说明-双击打开.html”是本指南的离线阅读版。发送完整预览压缩包，伙伴就能同时获得页面和说明。仅发送校园助手 HTML 也能体验，但不会附带说明。

**继续开发：**使用源码包，在项目目录安装依赖并启动开发服务。源码包不包含依赖目录，需要先执行 npm ci；npm run dev 的默认地址是 http://localhost:4200。npm run build 生成部署版 dist 和可直接打开的 standalone 文件。

**本地网站预览：**预览包带有 dist 和 scripts/serve.mjs。安装 Node.js 后执行 node scripts/serve.mjs，或在 Windows 执行 start-preview.cmd --server。默认地址 http://127.0.0.1:4300；端口占用时以窗口输出地址为准。需要保持服务运行。拒绝连接通常表示该端口没有运行中的服务，可改用双击 HTML。

dist/index.html 需要 HTTP 服务，不能当作独立文件双击。127.0.0.1 和 localhost 指访问者自己的电脑，不能作为分享给朋友的公网链接。GitHub 仓库用于保存源码，Release 用于下载文件；上传仓库不会自动发布网站。

## 2. 当前真的运行了什么

| 能力 | 本版实现 | 使用时的含义 |
| --- | --- | --- |
| 页面、搜索、筛选、收藏、论坛互动 | 浏览器里的真实界面与状态更新 | 操作可完成，但只改变本机记录，没有其他学生收到帖子 |
| 对话与推荐 | 对话使用示例回答；推荐从用户文字执行有限规则提取和本地内容匹配 | 推荐可以随文字变化，不是大模型理解 |
| 条件核对 | 根据用户确认的学校年度、在读情况和经历，执行固定规则 | 状态变化是真实计算，条件本身是虚构示例 |
| 准备清单 | 计算进度、手动勾选、关联预审、刷新保存与文本下载 | 记录的是准备过程，没有真实提交 |
| 计划书预审 | 预设初稿与修改稿，固定四项检查结果 | 展示检查与修改关系，没有分析上传文件 |
| 通用文件工具 | 选择文件、检查允许类型与大小、展示预设结果 | 不读取正文；换一个文件也不会生成针对它的真实结论 |
| 原文依据 | 预先写好的文件编号、版本、条款和关联附件 | 能打开、定位与核对，不代表检索到真实学校政策 |
| 算法处理状态 | 短暂的阶段提示与折叠说明 | 提示是演示节奏，不是模型正在计算的日志 |
| 保存与下载 | 当前浏览器本地保存；导出示例 TXT | 无账户、无云端同步、无后台文件存储 |

没有运行 LLM、Embedding、BM25、Rerank，也没有后端接口、外部资料检索、正式审核或真实学生画像服务。

## 3. 四个入口怎样配合

**小X：**初始页提问、三个快捷问题、两条推荐内容；对话中可继续追问，科研申请情景会显示依据、条件和下一步。

**广场：**“通知”展示制度类内容，“问答讨论”展示同学交流。可以搜索、切换高校范围、筛选主题、阅读详情、收藏、发帖与回复。讨论经验不能代替制度依据。

**智能体：**独立的文件审查与资料整理工具。科研事项中的计划书预审也使用这个入口，但与当前事项关联，可以把示例复核结果回写到清单。

**我的：**查看收藏、对话历史、资料记录与正在准备的事项；可以返回原对话继续，也可以删除对话。

## 4. 伙伴的算法图怎样体现在前端

主线是：可信文件 → 理解当前问题与上下文 → 找到适用依据 → 对照个人事实 → 判断缺口 → 回答或继续准备。

### 4.1 可信文件入库与知识组织

真实系统需要解析通知和附件、保存原文版本、建立父子分块和索引、抽取事项与规则，并由人工确认发布。

原型用两份关联的科研示例文件展示这一结果：DEMO-KY-2026-01《本科生科研项目申报说明》和 DEMO-KY-2026-A《附件 A · 计划书要求》。它们都标明云川大学、2026 秋季、版本 2026.1，以及条款位置。点击来源可读完整条款，第一份可以打开通知全文并定位条件。

这里预设的是“整理后的知识”，没有真正执行入库、文档解析或人工发布流程。

### 4.2 问题理解与上下文整合

包含科研和项目申请等有限关键词的问题进入科研情景。申请范围、在读情况和经历最初都是未知；只有用户在“补充个人信息”面板中确认后，才更新核对结果。附件名称、推荐兴趣和聊天中的发展目标不会自动成为资格证明。

同一对话保存当前科研事项与准备状态，追问时继续使用这一事项。普通问答仍可独立体验，不会全部变成办事流程。当前并非通用任务识别系统。

### 4.3 混合检索、精排与证据获取

算法图中的语义检索帮助找到意思相近的内容；BM25 帮助找到明确名称和关键词；合并去重与 Rerank 再挑选相关证据；回看完整原文和附件，避免只看零散片段。

前端通过处理阶段、来源编号、版本、完整条款与附件关联展示这种关系。科研核对末尾的“查看依据如何整理”说明检索顺序。当前直接使用固定的两份来源，不会生成向量、运行关键词检索或计算精排分数。

### 4.4 证据缺口驱动的回答与办事辅助

前端真正计算三项状态：学校年度、本科在读、课程项目或竞赛成果。每项都有条件、用户确认的事实、结果和来源。

| 状态 | 代表什么 | 界面效果 |
| --- | --- | --- |
| 已满足 | 确认的信息符合该项示例条件 | 可以结合其他条件判断是否继续准备 |
| 未满足 | 明确确认的信息不符合该项条件 | 提示条件暂未满足，不把它包装成通过 |
| 待确认 | 还没有足够个人信息 | 保留判断，可以补充，也可先准备清单 |
| 范围冲突 | 学校或年度不适用 | 暂不能使用这份文件判断资格，初始流程要求重新核对 |

示例资格关系是：范围匹配，并且本科在读，并且“课程项目经历或竞赛成果”至少具备一项。两类经历不是都必须具备。

合并结论先看范围冲突，再看明确未满足，再看未知，全部满足才提示可以继续准备。未知与未满足同时出现时，合并结论强调已知的未满足，逐项列表仍保留未知状态。

个人信息不足通过澄清面板补充；文件缺口用“截止时间无法确认”展示；范围冲突用重新核对展示。没有真实定向补检索，也没有实现规则例外、不同版本冲突的自动判定或检索预算控制。已有清单之后再改成范围冲突，清单会保留，资格结论仍更新为冲突。

用户选择继续后生成四项准备清单，计划书复核可以更新其中一项。这个回路展示“回答 → 下一步 → 状态更新”，没有自动提交申请或获得审核结果。

## 5. 从对话自动推荐的实际规则

不要求学生填写发展目标表单。它读取当前浏览器保存的**用户文字**，按时间顺序整理，跳过被忽略的消息，用有限关键词与句式识别四类方向：实习准备、学习提升、升学规划、科研探索；以及项目经历、简历表达、资料整理、方向探索四类准备需求。

“我想准备实习”显示为近期目标；“第一次找实习，需要准备什么？”显示为关注方向，不等于用户已经决定长期目标。明确提到自身经历较少时，用“积累项目经历”等积极方向展示，不给学生贴“缺陷”标签。

匹配顺序：过滤隐藏内容 → 按方向筛选 → 核对学校范围 → 对相关内容排序 → 最多展示两条，尽量兼顾资料与讨论。有限候选目录共十条，包含四份资料、两条通知和四条讨论；不会搜索整个广场或自动把新发帖子加入推荐目录。

本地排序规则：准备需求匹配加 10，方向匹配加 6，科研方向的通知额外加 2；同分沿用目录顺序。这些数字只是排序权重，不是准确率、可信度或申请成功概率。第一条取最高分，第二条优先选与第一条不同的“讨论 / 非讨论”类型。相关内容不足时少展示，不编造。

顶部明确选择的高校优先于对话中的学校；“全部高校”时参考已识别学校。通用资料与同学经验可以跨校阅读。学校未知时可能显示标明范围的校内通知，仍需另行核对适用条件。

“推荐依据”保留原话和原对话入口。同一句话中的多个信号合并展示。“理解有误”会忽略**整条用户消息**，该消息提供的目标、准备需求和学校都不再参与推荐；可能回到较早的有效依据。可以恢复被忽略的依据、暂停或恢复对话推荐、隐藏单条内容并恢复。

暂停只停止使用对话信号，仍展示探索内容，并保留高校筛选与隐藏偏好。删除对话后重新计算，可能采用其他尚未删除的对话。隐藏偏好按内容保存，不会因为换目标自动清空。

## 6. 五分钟体验路线

1. 首页发送：**我想准备实习，但项目经历不多，应该从哪里开始？**
2. 点击底部“小X”回到初始页，查看项目指南和实习讨论；打开“推荐依据”，查看同一句原话如何形成目标与准备方向。
3. 打开资料，读三个准备步骤并下载；返回首页，通过右侧菜单隐藏一条内容，再在推荐依据中恢复。
4. 首页点击科研申请快捷问题并发送。查看两份来源，打开“补充个人信息”，点击“使用示例信息”。三项条件变为已满足。
5. 生成准备清单，进入计划书预审；选择示例初稿并开始预审。看到两项待完善后，使用修改后的示例并复核。
6. 返回清单，观察已完成 2/4；手动勾选申请表与提交要求后为 4/4。下载清单，刷新或到“我的 → 正在准备”确认进度保存。

这是两个独立关系：推荐了解近期方向；科研核对确认当前事项的具体信息。无需填写推荐表单，但申请核对仍需要用户确认事实。

## 7. 特殊例子与预期效果

以下是明确的演示输入和操作。需要观察冷启动或第三人称例子时，请使用没有历史记录的浏览器环境；如果已有对话，旧依据可能继续生效。不要为了演示直接删除自己想保留的记录。

### 7.1 个性化推荐

| 场景与输入 | 操作与预期效果 | 说明 |
| --- | --- | --- |
| 没有用户对话 | 打开首页，显示“先看看这些方向”与探索内容 | 不假装已经了解学生 |
| 我想准备实习，但项目经历不多，应该从哪里开始？ | 发送后回首页；显示课程项目到作品集指南和实习讨论，依据为“实习准备 · 积累项目经历” | 自动读取用户文字，无需填表；两项理解共用一条原话 |
| 第一次找实习，需要准备什么？ | 发送后查看推荐依据，目标栏使用“最近关注的方向” | 提问主题不等于明确发展目标 |
| 我的朋友想准备实习，他没有项目经历，能给他建议吗？ | 在无旧依据的环境发送，回首页仍显示探索内容 | 这个明确第三人称例子不建立本人目标；复杂转述不保证都能理解 |
| 附件名为“没有项目经历.txt”，文字只谈朋友 | 添加附件并发送；仍不从文件名建立本人准备需求 | 附件元信息与个人推荐依据分开 |
| 我已经有项目经历了，我不打算找实习了，想先复习。我的课件和笔记很分散。 | 在实习对话中继续发送；回首页变为学习资料整理与复习讨论，旧“积累项目经历”依据移除 | 展示部分目标变化与改善表达；不是所有否定句都能识别 |
| 我是南湖理工大学的学生，想了解科研项目申请。 | 顶部保持“全部高校”；发送后回首页，不推荐云川大学专属科研通知，仍可看通用资料与科研讨论 | 推荐学校范围与科研事项资格独立；科研核对不会因此自动填入事实 |
| 对依据点击“理解有误” | 整条消息不再参与推荐；无其他有效信号时恢复探索内容；刷新后仍忽略 | 不是修改原话，也不是只删除一个信号 |
| 点击“恢复被忽略的依据” | 当前仍存在的被忽略消息重新参与计算，先前目标与准备方向可以恢复 | 恢复所有忽略记录，不能找回已删除对话 |
| 隐藏一条推荐，再暂停 / 恢复推荐 | 隐藏后换成其他相关内容；刷新仍隐藏；暂停展示探索内容；恢复重新按对话匹配 | 暂停不清空对话，也不恢复隐藏内容 |
| 删除最新学校或目标对话 | 从“我的 → 对话历史”删除，首页可能回到更早的有效目标，刷新后保持 | 有其他依据时不一定回到冷启动 |

### 7.2 条件、证据与材料准备

| 场景与操作 | 预期效果 | 它展示的关系 |
| --- | --- | --- |
| 首次发送科研快捷问题，不补充信息 | 三项待确认，合并结论还有 3 项待确认 | 缺信息不等于不符合 |
| 范围匹配、本科在读，只选择课程项目经历 | 三项已满足 | “或”条件满足一项即可 |
| 同样条件，把经历改成竞赛成果 | 仍为已满足 | 不强求同时有课程项目与竞赛 |
| 经历选择暂时没有这两类经历 | 此项未满足，合并结论有条件暂未满足 | 已确认不符合与未知分开 |
| 在读情况选择其他在读情况 | 本科在读条件未满足 | 不自动把其他身份当本科学生 |
| 学校年度选择其他学校或年度 | 范围冲突，暂不能据此判断；初始状态不能直接继续准备 | 其他学校的规则不能直接套用 |
| 保留未知，点击先准备清单 | 可以安排准备，条件仍待确认；修改信息后继续更新 | 准备进度与资格判断分开 |
| 在科研对话追问：什么时候截止？ | 回答示例文件未写明，目前无法确认；需要向管理老师核对 | 文件缺口不编造日期；没有真实补检索 |
| 上传名为“本科在读证明.pdf”的附件 | 显示附件名，条件仍待确认 | 文件名不能证明资格，正文没有被读取 |
| 初稿预审 | 四项中研究目标与成员分工已齐全，实施安排和老师确认记录待完善 | 预设材料缺口可解释，而非只有一个通过分数 |
| 使用修改后的示例并复核 | 四项内容已齐全，回清单由 1/4 变 2/4（此前使用完整示例信息） | 材料状态回写当前事项 |
| 手动标记另外两项后 4/4 | 清单完成，仍提示不代表已提交或获批 | 手动确认不是后台审核，也不证明实际日期已核实 |

清单里的“确认个人信息”表示信息已核对：明确未满足也属于“已核对”，不意味着资格通过；若重新改成未知或范围冲突，该项会回到未完成。材料内容齐全也不能推翻资格条件或适用范围判断。

### 7.3 通用文件工具与离线体验

从“智能体”进入独立文件工具，选择文件或使用示例材料，再点击处理、查看与下载结果。真实文件只用于展示选择状态和名称等信息；结果来自预设文本，没有内容读取、病毒检查、合规审查或智能归档。请不要把结果当作真实文件的分析结论。

使用双击版进入详情、聊天、下载和返回；地址中的 #/ 是正常的离线路由。完成操作后刷新，本地保存的记录会继续显示。离线页面不需要 HTTP 请求；如果通过文件系统打开，不需要 4300 端口运行服务。

## 8. 本地数据与已知限制

所有记录保存在当前浏览器的本地存储。HTTP 地址、浏览器、浏览器配置或离线文件位置不同，可能看到不同记录。分享包携带程序和初始示例，不携带你当前浏览器中的对话、收藏或准备进度。隐私模式、清理浏览器数据、存储禁用等情况可能导致记录不保留。

推荐目前只保留一个近期方向和一个准备需求，不是完整发展档案。关键词规则无法可靠理解所有否定、假设、引述、混合人物或多目标表达；明确第三人称与假设的部分语句会跳过，但不应据此宣称理解准确率。发现误解时请使用“理解有误”。旧版消息没有逐条时间时，跨对话先后顺序是近似处理。

本版不会做真实院校政策更新、资格验证、多版本规则冲突分析、例外审批、补检索循环、检索预算控制、真实材料修改或提交。阶段动画只用于说明流程；复核按钮切换预设材料，不会改写你的文件。一般聊天回复也是预设内容，没有实时搜索。

手机比例与窄屏可以在浏览器中体验；真实 iOS / Android 软键盘、触控和不同浏览器仍需要设备验收。支持毛玻璃的浏览器显示透明模糊，不支持时保留可读背景。
